# How to Fill Out the Status Report Template

Use [template.md](template.md) as your starting point. Copy it into a new file for each reporting period and fill in each section as follows:

## Header
- **Date:** The date you're writing/publishing the report (not the period start).
- **Reporting Period:** The start and end dates the report covers (e.g., one week or one sprint).
- **Author:** Your name.

## Summary
- Give a one- or two-sentence overview of how things are going.
- Pick a clear status: **on track**, **at risk**, or **delayed**. Don't leave this ambiguous — it's the first thing readers look for.

## Accomplishments
- List concrete, completed items from the reporting period.
- Prefer specific outcomes ("Deployed v2.3 to production") over vague statements ("worked on deployment").
- If relevant, reference ticket IDs (e.g., `[JIRA-123]`) so readers can look up details.

## In Progress
- List work that is actively underway but not yet finished.
- Include the owner if the report covers multiple people, so readers know who to ask.

## Blockers / Risks
- List anything preventing progress or threatening the timeline.
- Be specific about the impact and, if possible, what's needed to unblock it.
- If there are no blockers, write "None" rather than leaving the section empty.

## Next Steps
- List what you plan to focus on in the next reporting period.
- Keep this forward-looking — don't repeat items already listed under "In Progress" unless the plan has changed.

## General Tips
- Keep bullet points short — one line each where possible.
- Write for someone who has no other context; avoid internal jargon or unexplained acronyms.
